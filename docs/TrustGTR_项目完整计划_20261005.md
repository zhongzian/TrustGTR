## 02 研究问题与完整创新范围

### 核心问题

原 GTR 使用一个可学习全局表示 Q，按相位取片段，与局部输入经过二维卷积和残差融合。我们关注的不足是：不同预测样本需要的历史上下文不同；同一周期位置可能属于不同状态；过去有效的模式在漂移或突发变化时可能失效。

<!-- widths: 0.13,0.29,0.58 -->
| 模块 | 要解决的问题 | 拟建立的贡献 |
|---|---|---|
| A | 应该看哪段历史？ | 多个历史跨度中的状态条件检索与动态选择 |
| B | 检索应使用多少？ | 根据输入与预测一致性，校准历史修正的可靠性 |
| C | 怎样学会正确检索？ | 同相位、相似未来状态的正例与困难负例监督 |

研究视角以检索为中心：不只是增加频率或尺度，而是让当前样本决定历史候选、候选权重和拒绝程度。A/B/C 均保留独立开关；暂时无效的模块保留代码、负结果和下一版方案。

### 原始设想与当前实现需要分开

初始 A 是多个独立周期 Q，分别负责短、中、长周期；B 是特征残差门控；C 是“同周期位置 + 类似状态”的对比学习。当前版本已经改为真实训练历史 continuation 的预测校正，具体差异见后续三页。

**当前可支持：** ETTh1 单 seed 中，真实历史检索带来小幅正向结果。

**尚待支持：** B/C 独立收益；新版 Solar 泛化；多 seed 稳定性；真正独立长周期建模；更强对照下的优势。

### 面向投稿的判断

目标是至少形成两个可解释、可独立验证的贡献，但创新点数量不保证任何 CCF 会议录用。投稿论证应建立在方法区别、同协议收益、统计稳定性、机制证据和资源代价上；本阶段以实验质量和最快有效迭代为优先。

## 04 A：多周期历史记忆与检索

### v4/v5 的实际检索对象

训练段形成不可变历史库，每条记录包含观察窗、输入键和已经发生的后续 H 步。对当前预测起点 t，仅允许历史起点 j 满足 `j + H <= t`，并匹配 `j mod P = t mod P`；P 是官方基础周期。验证、测试数据永不写入该库。

候选按相对历史年龄分成短、中、长三档，各最多 64 条，总候选不超过 192。每档均匀覆盖可用历史，再按每通道的状态距离检索。

> 当前三库是“同基础相位、不同历史周期年龄”的记忆。配置中的 [24,168,720] 或 [144,1008,4320] 保留来源和库数量，当前并未分别按三个周期取模。不能把这一步写成已经证明日、周、月独立周期建模。

### 键、值与训练路径

- 15 维输入键：训练统计标准化的均值、log 标准差、趋势，加 12 个局部归一化形状分箱；局部 std 下限 0.1。
- 残差键编码器为 15→16→15，末层零初始化，使初始检索距离与验证诊断一致。
- 实际距离为平方欧氏距离；全局 top 3 后按逆距离和库 prior 加权。
- 历史未来先用候选观察窗归一化，再用当前观察窗的均值/尺度还原；只使用预测时可见输入。
- 路由为样本/通道条件化；C 直接训练同一检索键编码器。

### 当前限制与下一版

`global_topk` 先选候选再调库权重；若 top 3 全来自一个库，库 prior 在归一化中抵消，无法换入被排除的库。已实现的 `per_bank` 则每库各取 top 3，再连续混合；有正确性和梯度检查，尚无正式结果。

后续先单因素验证逐库路由。如果论文要主张独立多周期建模，还需实现真正不同周期的候选规则，并与当前历史年龄库比较。此为保留原创新范围的后续验证，不是现有事实。

## 05 B：可靠性门控与收益校准

### 当前预测融合

原 GTR 产生预测 y_base，历史库产生 y_hist；门控 g 为每样本/通道一个标量，在预测步之间共享。v5 的修正为：

`s = 0.2 * tanh(a / 0.2)`

`y = y_base + s * g * (y_hist - y_base)`

关闭 B 时 g=1；没有有效历史时直接输出 y_base。a 零初始化，初始预测和原模型随机流精确一致。s 允许有符号校正，不能无条件称为凸混合；其范围限制了修正幅度。

### 门控输入与训练监督

输入由当前观察窗统计、两路预测的 cosine 一致性、修正相对幅度和差异组成。描述符中的预测分支 detach，避免门控通过描述符改造专家。未来标签仅用于训练期最优混合系数：

`delta = s * (y_hist - y_base)`

`g_star = clip(<Y-y_base, delta> / (||delta||^2 + eps), 0, 1)`

g_star stop-gradient；校准损失按修正能量加权，系数 0.05。验证与测试仍使用纯 MSE，不使用门控 oracle。

### 需要证据支持的性质

g=0 回到当前共同训练的 GTR 分支，不能保证等于已经完成的 baseline checkpoint，也不能保证训练后“不伤 baseline”。已验证的是初始行为等价、推理不读未来和结构上的拒绝能力。

v5 加 B 后整体弱于 A5。下一步比较动态门控与固定门控，检查门控是否只是缩小有效修正；记录 oracle 标签分布、gate 饱和、校准误差和各库预测分歧。候选距离或库间分歧可作为后续可靠性输入，但一次只验证一个改动。

## 06 C：状态对比检索学习

### 正例与困难负例

使用训练目标的未来平均水平和趋势构造 regime；先减去观察窗水平，再除以观察窗尺度。候选必须同基础相位、因果可用，并与当前完整输入/目标窗口不重叠：`t-j >= T+H`。

在这些历史候选中，未来 regime 最近者作为正例，最远者作为困难负例；要求至少两个候选、正例足够相似、正负距离有区分。这样监督的不只是“同一时刻”，还包括“状态相似”。

### 当前损失与实现边界

`L_train = L_forecast + 0.05 * L_gate + 0.002 * L_contrast`

其中关闭的模块不保留对应 loss。对比温度为 0.1；v5 默认 cosine 正负 logits。query 未来只在训练 criterion 中读取；验证、测试和预测前向不接收 query 的未来。

历史候选及其已发生 continuation 来自固定训练段。与缓存过时 embedding 的队列不同，当前候选键在前向中使用同一编码器重新计算，因此恢复不需要动态跨 batch 缓存。

### 已解决的问题与未解决的问题

- 旧版 batch 内同相位候选在 Solar 的有效 anchor 仅约 3.55%；真实历史库使 ETTh1 ABC4/ABC5 的有效率约 93.66%。
- 有效 anchor 多只说明监督可用，不证明预测有效。C 在 AB5 背景下有小幅改善，但仍缺 AC5 对照。
- 实际检索是欧氏距离，v5 对比是 cosine，几何不一致。`contrast_metric='euclidean'` 已具备开关，未正式验证。

后续先补同版本 AC，再单独验证度量一致性。诊断主损失与辅助损失的编码器梯度大小和方向；不以对比 loss 下降代替检索质量或预测收益。

## 14 GPU 队列与失败恢复

### 已实现的调度机制

统一调度器后台运行、非阻塞轮询，最多三个实验。依据 GPU UUID、实时空闲显存、历史峰值与少量安全余量补位；能跑一个就跑一个，资源增加后再补，不能以虚假 tensor 囤积显存。

启动临界区用共享 flock 保护 GPU 选择、显存预留、任务登记与 PID 写入。恢复时重新登记收养的活任务，避免崩溃窗口漏算资源。记录每任务配置、日志、PID、状态、退出码和峰值。

<!-- widths: 0.32,0.68 -->
| 状态/错误 | 处理 |
|---|---|
| SUCCESS | 保存指标，归档并自动汇总，不重复启动 |
| OOM | 清理自身进程，更新估计与次数，指数退避回队列 |
| WAITING_RESOURCE | 保留队列、低频等待，不占 GPU |
| DATA / CONFIG / CODE_ERROR | 定位修复；新 ID 与 smoke 后再启动，不无限重跑 |
| NAN_OR_DIVERGENCE | 保存最后状态，诊断数值问题 |
| EXTERNAL_KILL | 完整兼容 checkpoint 才可恢复 |
| UNKNOWN_ERROR | 保存错误，有限诊断后暂停该任务 |

OOM 重试要求比上次启动时更多空闲显存或更大 GPU，不用清理后显存误作参照；退避记录 next_eligible_time，较多失败转长期资源等待。只管理本用户确认归属的进程。
